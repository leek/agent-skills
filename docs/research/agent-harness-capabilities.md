# Agent harness capabilities: Claude Code, Codex, Grok, agy

Question: all Claude, Codex, Grok, and agy settings, frontmatter support, mod support, tools, etc., stored in the repo with where each fact was found so it can be updated as the tools evolve.

Researched 2026-11-17 against Claude Code 2.1.326, Codex CLI 0.169.0, Grok 1.0.88, agy 1.5.10 (installed locally). "agy" is the Google Antigravity CLI (`agy --help`; docs at `antigravity.google`). Every section names its source and how to refresh it. Where a fact came from a summarizing fetch rather than a read of the full page, the section says so.

### Mods (Claude Code's in-process plugin extension; this is what "mod support" means for Claude)
Overview `https://code.claude.com/docs/en/plugins/mods/overview.md`; reference `.../plugins/mods/reference.md`; pages for create, interface, events, api, test, troubleshoot, admin, gallery (index in llms.txt under "Mods").
- A mod is a plugin whose `hooks/hooks.json` has `"modules": ["./register.js"]`; the module (`.js/.mjs/.cjs/.jsx/.ts/.mts/.cts/.tsx`, ES module) exports `register(on, options)`. Optional `types/index.d.ts`, `*.test.ts` run by `claude plugin test`. Works in CLI, Desktop Code tab, VS Code extension.
- Handler: `on(event, matcher?, async ($, e, next) => ...)`; middleware style via `next(e)`. Events include `tool.call`/`tool.check`, `skill.prompt`, `turn.step`, `process.spawn`, `settings.read`, `session.*`, `agent.*`, `ui.*`, `prompt.*`, `command.*`, `config.*`, `telemetry.log` (see reference for the full table).
- API namespaces on `$`: `plugin ui theme command tool agent model prompt turn session config settings env fs store state clock http process mcp audio telemetry`.
- Settings/env: `CLAUDE_CODE_PLUGIN_DIRS`, `CLAUDE_CODE_PLUGIN_DIR_WATCH`, `prependPlugins`, `appendPlugins`, `pluginConfigs`, `allowManagedModsOnly`, `allowModsToOverrideDenyRules`, `allowManagedHooksOnly`, `disableAllHooks`, `disableSideloadFlags`. Built-in guard `sec-default@builtin` (source: `github.com/anthropics/claude-code/tree/main/mods/sec-default`). Samples: `github.com/anthropics/claude-code-playground/tree/main/claude-code/mods` (unsupported).
- Mods are code with the user's permissions: install only from trusted marketplaces.

### Skills (`https://learn.chatgpt.com/docs/build-skills.md`)
- `SKILL.md` frontmatter documented: `name`, `description` only. Extra keys are tolerated (this repo's `docs/authoring.md` records Codex's `SkillFrontmatter` has no `deny_unknown_fields`; re-verify against `openai/codex` source if it matters).
- Optional `agents/openai.yaml` beside the skill: `interface.{display_name,short_description,icon_small,icon_large,brand_color,default_prompt}`, `policy.allow_implicit_invocation` (default true; false = explicit `$skill` only), `dependencies.tools[]` (`type: mcp`, `value`, `description`, `transport`, `url`).

Same-name skills are not merged. Symlinked skill folders are followed. Invoke with `$name` or `/skills`; implicit match by description.
- Disable: `[[skills.config]]` with `path` or `name` + `enabled = false` (last matching entry wins); `[skills.bundled] enabled = false`; `skills.include_instructions = false` drops the skills instruction block.

CLI: `codex plugin marketplace add|list|upgrade|remove`.

## What this unblocks

Answered at the level of structure, sources, and the settings/frontmatter/hook/plugin/tool surface for all four harnesses, with a refresh recipe per harness. Claude Code is the only one with a "mod" system (in-process JS/TS plugins); Codex and Grok have none, and agy's nearest equivalent is sidecars. This makes decidable: which frontmatter keys are portable (only `name` and `description` are common to all four, and the others tolerate or ignore extras except claude.ai uploads and agy's `additionalProperties: false` plugin manifest), whether to add `.agents/skills` mirrors, and where `docs/authoring.md` and `skills/harness-tools/SKILL.md` need updating (harness-tools pins agy 1.4.12 and Codex 0.166; both are now behind).
